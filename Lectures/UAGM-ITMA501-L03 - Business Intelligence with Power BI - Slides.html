Dashboarding Principles & Power BI

How visuals tell a story, how dashboards support decisions, and how to build an online-store report from CSV files.

Audience: decision makersTool: Power BI DesktopDataset: Online Store CSVsDuration: 60–90 minutes
1 · The purpose

A dashboard is a decision surface.

Every visual should answer a question, reduce uncertainty, or point to an action.

Executive

Are results healthy?

Revenue, orders, average order value, rating.

Manager

Where should we focus?

Categories, products, status, and time.

Analyst

Why is this happening?

Drill into segments and relationships.

Question first: Who is looking, what do they need to decide, and what evidence would change that decision?

Match the visual to the question.

Rule: position and length are easier to compare accurately than angle, area, or color intensity.
3 · Good vs. not ideal

Comparison: make the ranking obvious.

Good

Sorted horizontal bars

Cat ACat BCat CCat DCat E

One color, direct labels, descending order, readable category names.

Not ideal

Unsorted and decorative

Cat CCat ACat ECat BCat D

Equal-looking colors and arbitrary order make the reader work.

Teaching point: the reader should find the ranking without decoding the chart.
3 · Good vs. not ideal

Trend: time is an ordered sequence.

Good

Chronological axis, consistent intervals, clear movement.

Not ideal

Months reordered alphabetically or treated as unrelated categories.

Ask: “Can I tell what happened between January and June without reading every label?”
3 · Good vs. not ideal

Composition: show parts of a whole carefully.

Good

Shipped · 15%
Cancelled · 9%

Few categories, visible labels, and a meaningful total.

Not ideal
Nine similar slices
No ranking
No clear takeaway

When precise comparison matters, use a bar chart instead.

3 · Good vs. not ideal

A KPI needs context.

Good KPI card
Total Revenue · This month$128.4K▲ 8.2% vs. prior month

Value, period, comparison, and direction.

Not ideal
Revenue$128.4KNo period · no definition · no action context

A large number is not automatically a useful KPI.

Metric vs. KPI: a KPI has a definition, target or comparison, owner, and review cadence.

5 · Power BI workflow

Import → model → measure → visualize → explain.

  1. Get Data: import each CSV with Text/CSV.
  2. Model: create relationships and inspect table grain.
  3. Measure: write reusable DAX definitions.
  4. Visualize: place fields and measures into visual wells.
  5. Interact: add slicers and test cross-filtering.
  6. Explain: title the page and state the decision it supports.
Vocabulary: fields are columns; measures are reusable calculations; slicers are visible filters; the semantic model is tables, relationships, columns, and measures working together.
6 · Guided build · Step 1

Import six CSV files.

  1. Open Power BI Desktop → Get Data → Text/CSV.
  2. Import categories.csv, products.csv, customers_store.csv, orders.csv, order_items.csv, and reviews.csv.
  3. Choose Transform Data only when column cleanup is needed; otherwise choose Load.
  4. Ask: “What does one row represent in each table?”
Check before building: names, data types, dates, numeric fields, and blank keys.
6 · Guided build · Step 2

From discrete files to a semantic model.

The CSV files arrive separately. The relationships give them shared meaning.

Same idea as the SQL ERD: Power BI does not understand six files as one business system until keys connect them. The semantic model is the ERD made operational: relationships let filters, measures, and visuals travel across tables. Arrowheads show the direction from the lookup table toward the related detail table.
Ask before continuing: “If I filter category, how can Power BI reach order items and calculate revenue?” Trace categories → products → order_items.
6 · Guided build · Step 3

Build the semantic model.

FromTo
products[category_id]categories[category_id]
orders[customer_id]customers_store[customer_id]
order_items[order_id]orders[order_id]
order_items[product_id]products[product_id]
reviews[product_id]products[product_id]
reviews[customer_id]customers_store[customer_id]

Use Model view. Relationships should be one-to-many and single direction. If auto-detect fails, drag matching fields together.

6 · Guided build · Step 4

Define measures once.

Total Revenue = SUMX(order_items, order_items[quantity] * order_items[unit_price])
Total Orders = DISTINCTCOUNT(orders[order_id])
Avg Order Value = DIVIDE([Total Revenue], [Total Orders])
Avg Rating = AVERAGE(reviews[rating])
Cancelled Rate = DIVIDE(CALCULATE(COUNTROWS(orders), orders[status] = "Cancelled"), [Total Orders])
Why measures? They recalculate when a user selects a category, status, or date range.

Interactive guide: create a measure in Power BI

  1. Open Report view. Confirm the Fields pane is visible.
  2. Select a home table. Right-click order_items in the Fields pane.
  3. Choose New measure. Power BI opens the formula bar.
  4. Type the definition. Start with Total Revenue = and enter the DAX shown above.
  5. Press Enter. The measure appears with a calculator icon.
  6. Test it. Insert a Card visual and drag Total Revenue into it.
  7. Format it. Set the measure to currency and choose an appropriate decimal setting.
  8. Repeat. Create the remaining measures one at a time and verify each card.
6 · Guided build · Step 5

Build the page from the top down.

Top row

Cards

Total Revenue, Total Orders, Avg Order Value, Avg Rating, Total Customers.

Middle row

Story

Revenue by category bar chart and orders-by-status donut.

Bottom row

Diagnosis

Orders over time, Top 5 products table, and customers-by-country map.

Format last: validate numbers first, then set titles, units, colors, and spacing.
6 · Guided build · Step 6

Make the page interactive.

Slicers

  1. Category
  2. Order status
  3. Order-date range

Each one should answer a likely follow-up question.

Demonstrate

  1. Click a category.
  2. Watch cards and charts update.
  3. Click a bar and inspect cross-filtering.
  4. Drill from year to month.
SQL connection: the category bar is your GROUP BY category_id query, now visual and interactive.
7 · Read the page

Evidence → interpretation → action → limit.

Evidence

What does the visual actually show?

Interpretation

What might the pattern mean?

Action

What should be investigated next?

Example: “Electronics has the highest revenue in this report. It is a priority for follow-up, but the dashboard does not prove higher profit because cost and margin are not included.”
Close

A good dashboard tells the reader where to look next.

Choose the question. Choose the visual. Make the evidence easy to read. Add interaction only when it helps the decision.
