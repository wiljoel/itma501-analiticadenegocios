Datos relacionales y SQL de principio a fin

En este laboratorio utilizarás Supabase para consultar las tablas de Olist, practicarás 15 consultas SQL y exportarás un resultado reproducible para responder una pregunta de negocio. El informe en Power BI se construirá en el laboratorio de L03.

Duración: 2 horas Herramienta: Supabase SQL Editor Dataset: Olist Brazilian E-Commerce Modalidad: individual o grupos de 2–3

1. Objetivos del laboratorio

Al completar esta actividad podrás:

  1. Conectarte a una base de datos PostgreSQL mediante el SQL Editor de Supabase.
  2. Escribir consultas con SELECT, FROM, WHERE y operadores de filtrado.
  3. Resumir datos con COUNT, SUM, AVG, GROUP BY y HAVING.
  4. Combinar tablas usando INNER JOIN y LEFT JOIN.
  5. Exportar resultados SQL a un archivo CSV con un nombre reproducible.
  6. Comunicar un hallazgo de negocio indicando el método y una limitación.

2. Contexto de negocio y datos

Olist es un marketplace brasileño de comercio electrónico. El dataset contiene aproximadamente 100,000 órdenes de 2016 a 2018 distribuidas en nueve tablas relacionadas.

Ubicación de los datos: descarga el dataset desde la página de Olist Brazilian E-Commerce en Kaggle. El archivo contiene los nueve CSV utilizados en este laboratorio.

Tablas principales

olist_customers_dataset, olist_orders_dataset, olist_order_items_dataset, olist_products_dataset y olist_sellers_dataset.

Pregunta central

¿Quiénes son los 10 clientes que generan más ingresos y cuál es la categoría que más compran?

Importante: una fila de olist_order_items_dataset representa un artículo, no necesariamente una orden completa. Revisa siempre el nivel de detalle antes de sumar o contar.

6. Laboratorio A — 15 consultas contra Olist

Escribe y ejecuta cada consulta en Supabase. Antes de ver la solución, intenta describir qué resultado esperas. Coloca un comentario encima de cada consulta indicando qué devuelve.

Parte A — SELECT y WHERE (Q1–Q5)

-- Q1: Lista 10 clientes de São Paulo
SELECT customer_id, customer_city, customer_state
FROM   olist_customers_dataset
WHERE  customer_state = 'SP'
LIMIT  10;

-- Q2: ¿Cuántos productos cuestan más de R$500?
SELECT COUNT(*)
FROM   olist_order_items_dataset
WHERE  price > 500;

-- Q3: Estados de las órdenes que aparecen en el dataset
SELECT DISTINCT order_status
FROM   olist_orders_dataset;

-- Q4: Reseñas con la puntuación más baja
SELECT review_id, review_score, review_comment_message
FROM   olist_order_reviews_dataset
WHERE  review_score = 1
LIMIT  10;

-- Q5: Vendedores ubicados en la ciudad de Rio de Janeiro
SELECT seller_id, seller_city
FROM   olist_sellers_dataset
WHERE  seller_city = 'rio de janeiro';

Si Q5 no devuelve resultados, inspecciona primero algunos valores de seller_city; no cambies el filtro sin verificar la representación almacenada.

Parte B — Operadores (Q6–Q8)

-- Q6: Clientes cuya ciudad comienza con 'sao'
SELECT COUNT(*)
FROM   olist_customers_dataset
WHERE  customer_city LIKE 'sao%';

-- Q7: Órdenes de SP, RJ o MG
SELECT COUNT(*)
FROM   olist_orders_dataset o
JOIN   olist_customers_dataset c ON o.customer_id = c.customer_id
WHERE  c.customer_state IN ('SP', 'RJ', 'MG');

-- Q8: Artículos con precio entre R$100 y R$200
SELECT COUNT(*)
FROM   olist_order_items_dataset
WHERE  price BETWEEN 100 AND 200;

Parte C — Agregaciones (Q9–Q12)

-- Q9: Ingreso bruto total
SELECT SUM(price + freight_value) AS gross_revenue
FROM   olist_order_items_dataset;

-- Q10: Número de órdenes por estado, top 10
SELECT c.customer_state, COUNT(*) AS orders
FROM   olist_orders_dataset o
JOIN   olist_customers_dataset c ON o.customer_id = c.customer_id
GROUP  BY c.customer_state
ORDER  BY orders DESC
LIMIT  10;

-- Q11: Puntuación promedio por estado de la orden
SELECT o.order_status, AVG(r.review_score) AS avg_score, COUNT(*) AS reviews
FROM   olist_orders_dataset o
JOIN   olist_order_reviews_dataset r ON o.order_id = r.order_id
GROUP  BY o.order_status
ORDER  BY avg_score DESC;

-- Q12: Categorías con más de 500 productos únicos
SELECT p.product_category_name, COUNT(DISTINCT p.product_id) AS product_count
FROM   olist_products_dataset p
GROUP  BY p.product_category_name
HAVING COUNT(DISTINCT p.product_id) > 500
ORDER  BY product_count DESC;

Parte D — JOINs (Q13–Q15)

-- Q13: Información de orden y cliente
SELECT o.order_id, c.customer_state, o.order_status
FROM   olist_orders_dataset o
JOIN   olist_customers_dataset c ON o.customer_id = c.customer_id
LIMIT  10;

-- Q14: Productos sin nombre de categoría traducido al inglés
SELECT p.product_id, p.product_category_name
FROM   olist_products_dataset p
LEFT   JOIN product_category_name_translation t
       ON p.product_category_name = t.product_category_name
WHERE  t.product_category_name_english IS NULL
LIMIT  10;

-- Q15: Top 10 vendedores por cantidad de artículos vendidos
SELECT s.seller_id, s.seller_city, COUNT(*) AS items_sold
FROM   olist_sellers_dataset s
JOIN   olist_order_items_dataset oi ON s.seller_id = oi.seller_id
GROUP  BY s.seller_id, s.seller_city
ORDER  BY items_sold DESC
LIMIT  10;

7. Laboratorio B — Pipeline SQL

Responde esta pregunta con SQL: ¿Quiénes son los 10 clientes que generan más ingresos y cuál es la categoría que más compran? En L03 utilizarás el CSV resultante para construir el informe en Power BI.

Paso 1 — Calcular ingresos por cliente

Usa customer_unique_id para representar al cliente real y suma el precio más el flete de sus artículos.

WITH customer_revenue AS (
  SELECT c.customer_unique_id, c.customer_state,
         SUM(oi.price + oi.freight_value) AS revenue
  FROM   olist_customers_dataset c
  JOIN   olist_orders_dataset o ON c.customer_id = o.customer_id
  JOIN   olist_order_items_dataset oi ON o.order_id = oi.order_id
  GROUP  BY c.customer_unique_id, c.customer_state
),
top10 AS (
  SELECT customer_unique_id, customer_state, revenue
  FROM   customer_revenue
  ORDER  BY revenue DESC
  LIMIT  10
),
top_category_per_customer AS (
  SELECT c.customer_unique_id,
         COALESCE(t.product_category_name_english,
                  p.product_category_name) AS category,
         SUM(oi.price) AS category_spend,
         ROW_NUMBER() OVER (
           PARTITION BY c.customer_unique_id
           ORDER BY SUM(oi.price) DESC
         ) AS rn
  FROM   olist_customers_dataset c
  JOIN   olist_orders_dataset o ON c.customer_id = o.customer_id
  JOIN   olist_order_items_dataset oi ON o.order_id = oi.order_id
  JOIN   olist_products_dataset p ON oi.product_id = p.product_id
  LEFT   JOIN product_category_name_translation t
         ON p.product_category_name = t.product_category_name
  WHERE  c.customer_unique_id IN
         (SELECT customer_unique_id FROM top10)
  GROUP  BY c.customer_unique_id, category
)
SELECT t10.customer_unique_id, t10.customer_state, t10.revenue,
       tc.category AS top_category
FROM   top10 t10
JOIN   top_category_per_customer tc
       ON t10.customer_unique_id = tc.customer_unique_id
      AND tc.rn = 1
ORDER  BY t10.revenue DESC;
Clave: customer_id puede repetirse entre órdenes asociadas a una misma persona. Para una respuesta “por cliente”, agrupa con customer_unique_id.

Paso 2 — Validar y exportar a CSV

  1. Ejecuta la consulta y verifica que devuelva 10 clientes.
  2. Confirma que los ingresos estén ordenados de mayor a menor y que cada cliente tenga una categoría principal.
  3. En el panel de resultados de Supabase, selecciona Download CSV.
  4. Guarda el archivo como L02-top-customers.csv.
Entregable B: el archivo L02-top-customers.csv, que será la entrada del laboratorio de Power BI en L03.
