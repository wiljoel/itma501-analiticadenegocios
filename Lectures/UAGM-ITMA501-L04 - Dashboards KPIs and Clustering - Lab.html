Construye un dashboard de Olist en Power BI

Usarás la base de datos de Olist en Supabase que completaste en L02 para construir una página de Power BI orientada a una decisión de negocio. El objetivo no es llenar la página de gráficos: es comunicar evidencia clara y accionable.

Duración: 2 horasHerramienta: Power BI DesktopFuente: Supabase / OlistEntrega: .pbix + brief

1. Objetivos

  1. Conectar Power BI al proyecto de Supabase creado en L02.
  2. Elegir visuales según la pregunta y la forma de los datos.
  3. Crear tarjetas KPI, gráficos, una matriz y un filtro.
  4. Verificar agregaciones y explicar el nivel de detalle de cada resultado.
  5. Traducir patrones visuales en respuestas de negocio con evidencia y limitaciones.

2. Pregunta y audiencia

Construirás un dashboard para una persona gerente de operaciones o comercial que necesita identificar dónde investigar el desempeño de los pedidos.

Pregunta central: ¿Qué estados, meses o estados de pedido requieren atención y qué evidencia del dataset apoya esa conclusión?

Antes de abrir Power BI, escribe:

  1. La audiencia.
  2. La decisión que debe apoyar el dashboard.
  3. Los tres resultados que necesitará esa persona.

3. Conectar Power BI a Supabase

  1. Abre Power BI Desktop.
  2. Selecciona Home → Get data → PostgreSQL database.
  3. Obtén el host, puerto, nombre de base de datos y usuario desde Supabase → Project Settings → Database. No publiques tu contraseña.
  4. Selecciona el modo Import para este laboratorio.
  5. En el navegador, selecciona las tablas: olist_customers_dataset, olist_orders_dataset, olist_order_items_dataset y olist_order_reviews_dataset.
  6. Selecciona Load o Transform Data para revisar tipos de datos.
Si falla la conexión: usa el archivo L02-top-customers.csv como respaldo para practicar el diseño, pero documenta que no pudiste usar la conexión directa. No compartas credenciales de Supabase.

4. Revisar modelo y nivel de detalle

Antes de crear visuales, identifica qué representa una fila en cada tabla.

TablaGrano aproximadoUso en el dashboard
olist_orders_datasetUna fila por pedidoConteo de pedidos, fechas y estados
olist_order_items_datasetUna fila por artículo dentro de un pedidoPrecio, flete y revenue de artículos
olist_customers_datasetUna fila por dirección asociada al pedidoEstado del cliente
olist_order_reviews_datasetUna fila por reviewPuntaje promedio

Confirma las relaciones usando las claves disponibles. Si una medida se duplica por una relación, detente y revisa el grano antes de continuar.

5. Visual 1 — Tarjetas KPI

Crea tres tarjetas. Usa nombres completos y unidades claras.

  1. Total de pedidos: cuenta distinta de order_id.
  2. Gross revenue: suma de price y, si lo defines así, documenta si incluye freight_value.
  3. Puntaje promedio: promedio de review_score.

En una nota o tooltip, documenta el período y la definición de cada medida. Si el archivo no contiene una meta oficial, no inventes una: puedes usar una meta ilustrativa claramente rotulada.

6. Visual 2 — Comparación por estado

  1. Inserta un gráfico de barras.
  2. Usa el estado del cliente como categoría.
  3. Usa revenue como valor.
  4. Ordena de mayor a menor.
  5. Titula el visual Revenue por estado del cliente e incluye la unidad monetaria.
  6. Verifica al menos una cifra con una consulta SQL de L02 o con una tabla temporal en Power BI.
Interpretación: una diferencia de revenue describe el dataset analizado. No demuestra por sí sola que un estado sea más rentable en el futuro.

7. Visual 3 — Tendencia mensual

  1. Inserta un gráfico de líneas.
  2. Usa order_purchase_timestamp en el eje temporal.
  3. Agrega por mes y muestra conteo de pedidos o revenue.
  4. Revisa que los meses estén ordenados cronológicamente.
  5. Describe la dirección general: estable, creciente, decreciente, estacional o irregular.

Si Power BI crea una jerarquía automática que no funciona, usa una columna de fecha o una tabla calendario. Documenta cualquier transformación.

8. Visual 4 — Matriz de estado de pedido

  1. Inserta una matriz.
  2. Coloca el estado del cliente en las filas.
  3. Coloca order_status en las columnas.
  4. Usa conteo distinto de pedidos como valores.
  5. Activa totales si ayudan a comparar.

Utiliza esta matriz para responder: ¿qué estados concentran pedidos cancelados, entregados o en proceso?

9. Filtro e interacción

  1. Agrega un slicer para estado del cliente o order_status.
  2. Selecciona un estado y observa qué tarjetas y gráficos cambian.
  3. Haz clic en una barra y revisa el cross-filtering.
  4. Corrige interacciones que confundan o no aporten a la pregunta.
  5. Limita el número de filtros visibles; cada control debe responder una pregunta de seguimiento.

10. Diseño y revisión

Organiza la página en esta jerarquía:

  1. Título, audiencia y período.
  2. Tarjetas KPI.
  3. Gráfico principal de comparación o tendencia.
  4. Matriz o detalle diagnóstico.
  5. Slicer y nota metodológica.

Revisa alineación, tamaño de letra, formato de números, contraste, títulos explícitos y uso consistente del color. Elimina visuales decorativos o repetidos.

11. Convertir visuales en respuestas

Contesta usando tu dashboard:

  1. ¿Cuáles son los tres estados con mayor revenue?
  2. Para el estado seleccionado, ¿qué estados de pedido predominan?
  3. ¿La tendencia mensual muestra estabilidad, crecimiento, descenso o estacionalidad?
  4. ¿Qué pregunta adicional debes responder antes de recomendar una acción?
Formato: Evidencia — qué muestra el visual; Interpretación — qué podría significar; Acción — qué investigar o hacer; Limitación — qué no demuestra el dashboard.

12. Entrega

Entrega los siguientes archivos:

  1. L04-olist-dashboard-<apellido>.pbix.
  2. Un brief de una página en PDF o documento de texto.

El brief debe incluir:

  • Audiencia y decisión.
  • Tres hallazgos con evidencia numérica o visual.
  • Una recomendación o próximo paso.
  • Una limitación del dataset, del modelo o de la interpretación.
  • Definición de las tres tarjetas KPI.
No concluyas causalidad. “El estado X tiene mayor revenue en este dataset” es una descripción. “El estado X causa mayor revenue” no está justificado por este dashboard.
Fuente principal: tablas Olist cargadas en Supabase durante L02. Usa L02-top-customers.csv solamente como respaldo si la conexión directa no funciona.
